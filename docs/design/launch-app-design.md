## 0. 공통 원칙

- **MVP 흐름과 공존하지 않고 바꾼다.** 출시 기준 티켓은 새 표시값(예: `deliveryMode = "curatedV2"`, 또는 `flow = "launchV1"`)을 달고, 앱은 지금처럼 모르는 방식의 티켓을 "이전 방식 촬영"으로 안내한다(지금 `isCurated` 처리와 같은 방식). MVP 교차 조합·현장 실증이 끝난 뒤 단계별로 바꾼다.
- **지금 구조를 그대로 쓴다.**
  - 순수 규칙은 `SBSNCore`에 두고 단위 시험한다(예: 공개 위치 계산, 수락 시한, 편집 기간, 연락처 탐지, 촬영 길이).
  - Firestore 접근은 `SBSNBackend`의 `nonisolated static` + `AsyncThrowingStream` 리스너 패턴(`FirestoreListeners`)을 따른다.
  - 두 앱이 같이 쓰는 화면은 `SBSNUI`(지금 `TicketChatView`·`ParticipantsMapView`)에 둔다.
  - 쓰기는 서버 커밋 뒤 화면을 바꾼다(`CustomerTicketView`의 `ticketBeforeWrite` 방식).
  - 시한(5분 수락, 24시간 잠금, 7일)은 **서버 시각 기준**이다. 앱은 표시만 하고, 판정은 규칙·함수가 한다.
- **초 단위 카운트는 쓰지 않는다**(D051). 남은 시간은 분 단위 또는 "14:10까지" 같은 시각으로 보인다.
- **교차 조합**: 상태 이름·문구·시험 식별자(`accessibilityIdentifier`)를 Android와 맞춘다. 단계마다 iOS ↔ Android 네 조합으로 한 사이클을 본다.
- **예시 화면 정리**: 실제 화면이 된 예시(`CustomerFeatures`·`PhotographerFeatures`의 작가 프로필·활동 위치·휴게·수락 설정·바구니·계정 연결·전문 보정 등)는 그 단계에서 예시 목록에서 뺀다(D036 때 P6·P8과 같은 방식).

## 1단계 — 계정과 지도

### 1.1 로그인·계정 연결(두 앱)

- 방향(권장, 질문 Q1): **고객은 로그인 없이 지도를 둘러볼 수 있고**, 채팅·신청·구매 때 로그인한다. 지금 익명 계정을 그대로 두었다가 로그인하면 그 계정에 **연결**(`link`)해 uid를 유지한다. **작가 앱은 처음부터 로그인**한다(작가 등록·정산 대상이고, 공개 위치를 발행한다).
  - 근거: 심사 지침 5.1.1(v) "계정 기능이 핵심이 아니면 로그인 없이 쓰게 하라", 4.8 "Google 로그인을 넣으면 같은 조건의 다른 로그인(Apple 로그인)도 넣어라"(2026-10-16판).
- 화면(공용 `SBSNUI.SignInSheet`)

```
┌──────────────────────────────┐
│  십분스냅에 로그인             │
│  채팅과 촬영 신청은 로그인 뒤   │
│  할 수 있습니다.                │
│                              │
│  [  Apple로 계속하기      ]   │  ← 위에 둔다(같은 크기)
│  [ G  Google로 계속하기   ]   │
│                              │
│  계속하면 이용약관·개인정보     │
│  처리방침에 동의합니다 ▸        │  ← 동의 방식은 정책 세션 안
│                  [나중에]     │  ← 고객만(둘러보기로 돌아감)
└──────────────────────────────┘
```

- 연결 흐름
  1. 익명 사용자에 Apple·Google 자격 증명을 `link`한다. 성공하면 uid가 같아 티켓·찜·구매·presence가 그대로다.
  2. **이미 다른 계정에 연결된 자격 증명**(`credentialAlreadyInUse` 17025)이면: 그 계정으로 로그인(`signIn`)하고 지금 익명 계정의 기록은 버린다. 진행 중 티켓(`customers/{uid}.activeTicketId`)이 있으면 막고 "진행 중인 촬영을 끝낸 뒤 로그인을 바꿔 주세요"로 안내한다. 익명 계정의 데이터를 옮길지는 백엔드 결정(B1-2).
  3. 로그인 계정이 바뀌면(uid 변경) 세션이 리스너·FCM 토큰 등록·로컬 활성 티켓을 새 uid로 다시 시작한다. 지금 `CustomerSession.reissueAccount()`(디버그 "익명 계정 재발급")와 같은 경로를 정식화한다.
- 계정 삭제(마이 → 계정 → 계정 삭제, 두 앱)

```
┌──────────────────────────────┐
│ ‹ 계정 삭제                    │
│ 삭제하면 되돌릴 수 없습니다.     │
│ • 산 사진은 사진 앱에 남습니다   │
│ • 거래 기록은 법에 따라 n년      │  ← 문구는 정책 세션
│   보관 뒤 지웁니다              │
│ • 진행 중인 촬영이 있으면        │
│   삭제할 수 없습니다            │
│ [Apple로 다시 확인하고 삭제]    │  ← 로그인 수단에 맞춰
└──────────────────────────────┘
```

  - Apple 로그인 사용자는 다시 Apple 로그인으로 authorization code를 받아 `Auth.revokeToken(withAuthorizationCode:)` 뒤 삭제한다(Firebase가 Apple 토큰을 저장하지 않음).
  - 서버 데이터 삭제·익명화는 호출형 함수 하나로 한다(B1-3). 앱은 함수 성공 뒤 로그아웃하고 로컬(활성 티켓 ID, 작가 앱 티켓 폴더, 캐시)을 지운다.
- 바뀌는 파일
  - `SBSNBackend/Backend.swift`: `SignIn` actor → 계정 서비스(익명 시작, `link`, `signIn(with:)`, 로그아웃, 삭제, 로그인 상태 스트림). 동시 로그인 한 번만 하는 지금 보호는 유지
  - 새 `SBSNBackend/AccountService.swift`(Apple nonce·Google 자격 증명 만들기, 오류 코드 → 안내 문구)
  - 새 `SBSNUI/SignInSheet.swift`, `SBSNUI/AccountDeletionView.swift`
  - `sbsn/CustomerSession.swift`, `sbsnPhotographer/PhotographerSession.swift`: uid 변경 처리, 로그인 필요 시점 게이트
  - `sbsn/ContentView.swift`(로그인 실패 화면), `sbsn/Tabs/CustomerMyTab.swift`·`sbsnPhotographer/Tabs/PhotographerTabs.swift`(계정 섹션, 예시 "계정 연결" 제거)
  - 두 앱 entitlements(Sign in with Apple), Info.plist URL Types(`REVERSED_CLIENT_ID`), `GoogleService-Info.plist` 다시 받기(커밋하지 않음), 패키지 `GoogleSignIn` 10.1.0 이상(Firebase 13과 맞는 판)
- 재사용: 지금 `SignIn` actor의 "진행 중인 로그인 함께 기다리기", 디버그 "익명 계정 재발급"(시험용으로 남김)
- 위험
  - **같은 Apple·Google 계정이면 두 앱의 uid가 같다**(Firebase Auth uid는 프로젝트 단위). 지금은 앱마다 익명 uid가 달랐다. 작가가 고객 앱도 쓰면 같은 uid가 `customers/{uid}`와 `photographerPresence/{uid}`를 함께 갖는다. 자기 자신 매칭은 규칙(`customerUid != photographerUid`)이 막는다. 역할은 "어느 앱인가"가 아니라 작가 등록 문서로 정해야 한다(B1-4, 질문 Q2).
  - 작가가 폰 두 대에서 같은 계정으로 촬영 가능을 켜면 presence를 두 곳에서 쓴다. 기기 하나만 발행하게 할지 정해야 한다(B1-5).
  - Apple: 2026-01-01부터 한국 개발자는 Services ID를 새로 등록·수정할 때 서버 간 알림 엔드포인트(이메일 전달 변경·계정 삭제 알림)를 넣어야 한다. Firebase 설정에 Services ID가 필요하므로 엔드포인트가 먼저 있어야 한다(B1-6).
  - 익명 계정 30일 자동 삭제(Identity Platform)를 켜면 둘러보기만 한 사람의 기록이 지워진다. 연결된 계정은 지우지 않는다.
- 백엔드에 필요한 것: B1-1~B1-6("백엔드에 필요한 것" 표)

### 1.2 Google Maps SDK 전환(키·용량·약관·MapKit 대비 위험)

외부 사실은 2026-11-22에 공식 문서로 확인했다(출처는 끝의 "확인한 외부 사실").

| 항목 | 내용 | 설계 |
| --- | --- | --- |
| 설치 | Maps SDK for iOS 11.4.0, SPM `googlemaps/ios-maps-sdk`, 제품 `GoogleMaps`. 11.3.0부터 최소 iOS 17. Xcode 26 이상 | `SBSNUI` 패키지 의존성에 추가, "다음 주 버전 11까지"로 고정 |
| 용량 | 기기용 IPA 평균 +5.7MB(공식) | 두 앱 각각. 허용 범위로 본다 |
| SwiftUI | 공식 SwiftUI 뷰 없음. `UIViewRepresentable` + delegate 코디네이터 필요 | 공용 래퍼 `SBSNUI.GoogleMapView` 하나를 만들어 두 앱의 지도 세 곳에 쓴다 |
| 키 | 앱마다 키 하나, "iOS apps" 제한(번들 ID) + API는 Maps SDK for iOS만. 앱 안에 들어가고 교체에 앱 업데이트가 필요. Maps SDK는 App Check 대상 아님 | **공개 저장소라 키를 커밋하지 않는다**: git 제외 `Secrets.xcconfig` → Info.plist 값 → 시작할 때 `GMSServices.provideAPIKey`. `GoogleService-Info.plist`와 같은 방식 |
| 가격 | map ID 없이 만든 지도는 "Maps SDK" SKU(무료 한도 무제한). map ID(클라우드 스타일)를 쓰면 "Dynamic Maps" SKU(월 1만 회 무료, 이후 유료). 결제 계정 필수 | **map ID를 쓰지 않는다.** 다크 모드는 `overrideUserInterfaceStyle`로 지정한다(SDK 기본값은 문서끼리 달라 명시한다) |

  - Android는 이미 Google Maps라 같은 지도 위에서 교차 조합 화면을 비교하기 쉬워진다.
- 되돌리기: 래퍼 뒤에 지도 구현을 숨기면(입력 = 핀 목록·카메라, 출력 = 선택·보이는 범위) MapKit으로 돌아가기 쉽다.

### 1.3 지도 화면(고객): 화면 범위 작가 표시, 축소 시 숫자 묶음

```
┌──────────────────────────────┐
│ (지도 | 목록)          [필터] │  ← 목록·필터는 지금 예시 자리
│                              │
│      ●김작가          ③       │  ← 200m 칸 안 무작위 점(1분 갱신)
│            ●박작가            │     ③ = 축소했을 때 묶음
│   ☕이작가(휴게 · 점심 13:00까지)│  ← 휴게 중 표시(신청 불가, 채팅 가능)
│        ◉ 나                   │
│                    [⌖ 내 위치] │
│ ┌──────────────────────────┐ │
│ │ 김작가 · 촬영 가능           │ │  ← 핀을 누르면 하단 카드
│ │ 추천 20분 · 평균 2시간 안 전달 │ │
│ │ 8,000원부터 [결제 자리 문구]  │ │
│ │ [프로필 ▸]   [채팅하기]      │ │
│ └──────────────────────────┘ │
│ Google                        │  ← 로고는 가리지 않는다
└──────────────────────────────┘
```

- 화면 범위 조회: 지도를 움직여 멈추면(`idleAt`) 보이는 범위로 다시 조회한다. 서버가 주는 범위 조회 방식(지오해시·칸 ID 범위, B1-7)에 맞춘다. 한 번에 최대 100명(지금 규칙의 `limit`과 같은 방식).
- 묶음: 확대 수준에 따라 화면을 칸으로 나눠 한 칸에 둘 이상이면 숫자 원으로 보인다. 원을 누르면 그 칸으로 확대한다. 순수 함수(`SBSNCore`)로 만들고 단위 시험한다.
- 공개 위치: 작가 앱이 정밀 위치를 공개 문서에 쓰지 않는다. 200m 칸 안의 무작위 점을 누가 만드는지는 B1-8(권장: 서버 함수 또는 작가 앱이 **칸만** 올리고 점은 서버가 만든다). 같은 칸에 머무는 동안 점을 바꾸지 않으면 쓰기와 노출 정보가 함께 준다(LAUNCH_PLAN 위험 5와 같은 취지).
- 휴게·상태 표시: presence의 상태(촬영 가능 / 휴게 + 사유·끝 시각)를 핀 모양과 카드에 보인다.
- 바뀌는 파일

## 2단계 — 매칭·채팅·작가 상태·촬영 길이

### 2.1 고객: 작가 프로필 → 대화 → 촬영 신청

- 흐름: 지도 핀 → 하단 카드 → (프로필) → **채팅하기**(로그인 필요) → 대화방에서 촬영 시간을 정해 **신청** → 작가가 5분 안에 수락하면 매칭 → 위치 공유 시작.
- 작가 프로필

```
┌──────────────────────────────┐
│ ‹ 김작가                       │
│ [사진]  김작가                 │
│        촬영 가능 · 18:00까지    │
│ 추천 촬영 20분 · 평균 2시간 안 전달│  ← 평균은 서버 집계(3단계)
│ 활동 지역: 홍대·연남(반경 2km)   │  ← 홍보용(실제 가능 범위와 별개)
│ 소개: …                        │
│ 촬영 8,000원부터 · 사진 장당 …   │  ← 가격 표시만(결제는 4단계)
│ 샘플 사진(나중)                 │
│        [채팅하기]               │
└──────────────────────────────┘
```

- 대화방 + 신청(작가별 대화방, 같은 작가와 다시 촬영하면 같은 방)

```
┌──────────────────────────────┐
│ ‹ 김작가 · 촬영 가능   [🗺][…] │  ← 매칭 전에는 위치 단추 없음
│ ─── 11/18 촬영 20분 · 완료 ─── │  ← 지난 티켓 구분선(티켓 단위 내역)
│ …                              │
│ ─── 오늘 ───                    │
│ 고객: 지금 경복궁인데 가능할까요? │
│               작가: 네 가능해요  │
│ ┌──────────────────────────┐ │
│ │ 촬영 시간  [－] 20분 [＋]    │ │  ← 10분부터 5분 단위(상한은 Q7)
│ │ 촬영료 [결제 자리]           │ │
│ │        [촬영 신청]           │ │
│ └──────────────────────────┘ │
│ [＋사진][메시지 입력…]  [보내기] │
└──────────────────────────────┘
```

- 신청 뒤(고객)

```
│ ─── 촬영 신청 20분 · 14:10까지 수락 대기 ─── │  ← 시스템 메시지, 초 없이 시각
│ [신청 취소]                                   │
```

  - 작가가 수락하면 "매칭됐습니다 · 위치를 공유합니다"로 바뀌고 위치 단추가 생긴다. 시간이 지나면 "작가가 5분 안에 수락하지 않아 신청이 취소됐습니다"(자동 취소, 서버 판정).
  - 한 고객은 동시에 한 신청만(지금 고객 잠금 `customers/{uid}`와 같은 취지). 여러 작가에게 동시에 신청할지는 Q5.
- 바뀌는 파일
  - 새 `sbsn/Chat/ChatRoomView.swift`(고객 대화방·신청 막대), 새 `sbsn/Map/PhotographerProfileView.swift`(예시 `photographerProfile` 대체)
  - `sbsn/Map/PhotographerMapView.swift`: "이 작가와 촬영하기"(즉시 확정 트랜잭션) → 채팅하기
  - `sbsn/Ticket/CustomerTicketView.swift`: 단계에 "신청됨(수락 대기)" 추가. 만남 단계는 대화방이 중심이 되고 지도는 1.4 화면
  - `SBSNBackend/TicketService.swift`: `confirm` → `request(durationMinutes:)`, `withdraw`(신청 취소). 수락·자동 취소는 작가·서버 쪽
  - `SBSNCore/Ticket.swift`: `TicketPhase`에 `requested`, `expired`(자동 취소) 추가, 촬영 길이·연장 필드
- 위험
  - 지금 "고객 확정 = 작가 잠금" 트랜잭션·규칙(D008 레드팀 결과)을 다시 설계한다. 신청 중 작가 잠금 여부, 같은 작가에게 동시에 들어온 여러 신청의 처리(B2-2)가 정해져야 화면이 정해진다.
  - 5분 시한은 서버 시각 판정이다. 작가 폰이 늦게 받은 알림으로 수락을 누를 때 이미 만료된 경우를 안내해야 한다.

- 알림: "새 촬영 신청 · 20분 · 14:10까지 수락"(time-sensitive, 지금 매칭 알림과 같은 조합). 알림을 누르면 대화방.
- 홈(촬영 탭)

```
┌──────────────────────────────┐
│ 촬영 가능 · 반경 3km · 18:00까지 │
│ [변경] [휴게] [끄기]           │
│ ⚠ 최근 7일 자동 취소 2회: 한 번  │  ← 경고(제재 초안: 3회째 30분 제한)
│   더 놓치면 30분 동안 새 신청을   │
│   받지 못합니다                 │
│ 새 신청                        │
│ ┌──────────────────────────┐ │
│ │ 고객 A · 20분 · 14:10까지   │ │
│ │ "경복궁 정문 근처예요"       │ │  ← 마지막 메시지
│ │ [대화 보기]  [거절] [수락]   │ │
│ └──────────────────────────┘ │
│ 공개 대기 1건 ▸                 │  ← 지금 그대로

```

  - 제한 중이면 "15:02까지 새 신청 제한(확정된 촬영·채팅은 그대로)" 배너, 촬영 가능 토글은 켜져 있어도 지도에 "신청 불가"로 보일지 Q6.
  - 거절은 사유를 고른다(아래 2.3 취소 사유와 같은 목록에서 작가용). 거절은 제재 집계에서 뺄지 Q6.

  - `SBSNBackend/PhotographerPush.swift`: 알림 종류 `request`(지금 `match` 대체), 탭 라우팅
  - 새 `sbsnPhotographer/Chat/PhotographerChatRoomView.swift`

### 2.3 대화방 공통: 연락처·링크 제한, 사진 메시지, 취소 사유·상호/일방

- 공용 `SBSNUI.ChatRoomView`(지금 `TicketChatView` 확장): 대화방 단위 메시지, 티켓 구분선, 시스템 메시지(신청·수락·자동 취소·시작·종료·취소 사유).
- **연락처·링크 제한**: 보내기 전에 앱이 전화번호·이메일·URL·메신저 아이디 모양(예: "카톡 아이디", "오픈채팅")을 찾아 막고 입력창 위에 "연락처와 링크는 보낼 수 없습니다(운영정책 ▸)"를 띄운다. 앱 검사는 편의일 뿐이고 **서버도 같은 규칙으로 막아야 한다**(B2-5). 탐지 규칙은 `SBSNCore`에 두고 Android와 같은 시험 사례를 쓴다.
- **사진 메시지**: `＋사진` → PhotosPicker 1장 → 긴 변 1,280px·JPEG 품질 0.7 정도로 줄이고 **메타데이터(GPS 포함)를 모두 지운다**(D037의 고화질본과 다르다. 채팅 사진은 촬영 결과물이 아니다). 말풍선에 썸네일, 누르면 전체 화면.
  - 재사용: `PhotoPreviewRenderer`(축소·인코딩), 미리보기처럼 메타데이터 없이 인코딩하는 경로
- **취소 사유**: 매칭 뒤 촬영 시작 전 취소는 시트에서 사유를 고른다.

```
┌──────────────────────────────┐
│ 촬영을 취소할까요?              │
│ ( ) 일정이 바뀌었어요            │
│ ( ) 작가(고객)와 연락이 안 돼요   │
│ ( ) 만나기로 한 곳에 갈 수 없어요  │
│ ( ) 서로 이야기해서 취소해요      │  ← 상호 취소 표시
│ ( ) 기타 [메모…]                │
│ [돌아가기]        [촬영 취소]    │
└──────────────────────────────┘
```

  - 상대 쪽에는 대화방에 "고객이 취소했습니다 · 사유: 일정 변경"이 남고, 한 번만 "이 취소는 [서로 이야기한 취소] [일방적인 취소]"를 고를 수 있다(D051 "상대방이 상호/일방을 남긴다"). 누가 무엇을 쓰는지는 B2-6.
- 바뀌는 파일: `SBSNUI/TicketChatView.swift` → `ChatRoomView`, `SBSNBackend/TicketChatService.swift` → 대화방 서비스(메시지 종류: 글·사진·시스템), `SBSNCore/ChatMessage.swift`(종류·사진 경로·티켓 ID), 새 `SBSNCore/ContactFilter.swift`, `sbsn/Ticket/PlaceholderSheets.swift`(지금 신고·차단 예시 시트는 그대로)
- 위험: 대화방이 티켓 밖으로 나오면 지금 규칙(티켓 참여자만 메시지)과 알림 함수(`notifyPhotographerOfMessage`·`notifyCustomerOfMessage`)를 바꿔야 한다. 매칭 전 대화는 위치정보·개인정보 고지 범위가 달라질 수 있다(정책 세션).

### 2.4 작가 상태: 촬영 가능 켜기(반경·종료 시각), 휴게, 프로필

- 촬영 가능 켜기 시트

```
┌──────────────────────────────┐
│ 촬영 가능 켜기                  │
│ 이동할 수 있는 반경              │
│ ( ) 1km  (•) 3km  ( ) 5km      │  ← 값 목록은 Q8
│ 끝나는 시각                     │
│ [ 18:00 ⌄ ]  (1시간 뒤·2시간 뒤…)│
│ 고객 지도에는 200m 단위로 대략     │
│ 위치가 보입니다(고지 ▸)          │
│ [취소]              [켜기]      │
└──────────────────────────────┘
```

  - 끝나는 시각이 되면 자동으로 꺼진다. 앱이 꺼져 있어도 지도에서 사라지게 서버가 판정해야 한다(`availableUntil`, B2-7). 앱은 30분 전에 "곧 촬영 가능이 꺼집니다 [연장]" 알림(로컬 알림)을 띄운다.
  - 반경의 뜻(고객이 반경 밖이면 신청 불가인지, 지도 표시 범위인지)은 Q8.
- 휴게: `[휴게]` → 사유(점심·잠깐 쉼·이동 중·기타)와 시간(30분·1시간·직접) → 지도에 "휴게 · 점심 13:00까지", 채팅은 받음. 휴게 중 신청 가능 여부는 Q6. 끝나면 자동으로 촬영 가능으로 돌아온다.
- 프로필 편집(마이 → 프로필): 이름·사진·소개, 활동 지역·반경(홍보용), 추천 촬영 시간(10분부터 5분 단위), 평균 전달 시간(서버 계산, 표시만). 예시 `portfolio`·`activityArea`·`breakTime`·`requestPolicy`를 대체한다.
- 바뀌는 파일: `sbsnPhotographer/PhotographerHomeView.swift`(토글 → 시트), 새 `sbsnPhotographer/Availability/AvailabilitySheet.swift`·`BreakSheet.swift`, 새 `sbsnPhotographer/Tabs/PhotographerProfileEditor.swift`, `SBSNBackend/PhotographerDirectory.swift`(반경·종료 시각·휴게 필드, 프로필 문서), `SBSNCore/Presence.swift`
- 재사용: 지금 이름 입력(`displayName` 1~39자 규칙), 위치 권한 흐름, 백그라운드 위치 세션(`PhotographerLocationTracker`)

### 2.5 타이머 개편: 초 단위 제거, 시작 버튼 위치, 연장 자리

- 촬영 중(두 앱)

```
┌──────────────────────────────┐
│ 김작가와 촬영 중                │
│                              │
│        12분 남음               │  ← 분 단위(1분 미만은 "곧 끝남")
│   ▓▓▓▓▓▓▓▓░░░░░░  20분 촬영     │
│   (5분 연장됨)                  │
│                              │
│ [5분 연장 신청]                 │  ← 고객. [결제 자리], 작가 동의는 Q9
│ ─────────────────────────── │
│ [💬 채팅]           [… 더 보기] │  ← 종료는 작가 쪽 "…" 안(확인 다이얼로그)
└──────────────────────────────┘
```

- **시작 버튼 위치**: 지금은 하단 막대에 [취소]와 [촬영 시작]이 나란히 있어 잘못 누르기 쉽다. 바꾼 안:
  - 취소는 상단 `…` 메뉴로 옮긴다(사유 시트로 이어짐).
  - 하단에는 [촬영 시작] 하나만 두고, 누르면 확인 다이얼로그 "만나서 촬영 안내를 마쳤나요? 시작하면 20분 촬영이 시작됩니다".
  - 대화방 입력창과 시작 버튼 사이를 띄워 키보드·보내기와 겹치지 않게 한다.
- 연장: 2단계에서는 "결제 없이 5분 연장"으로 기록만 한다(`PaymentPlaceholderSheet` 재사용). 연장 결제·작가 동의는 Q9, 결제는 4단계.
- 끝: 정한 길이가 지나면 지금처럼 작가 폰만 진동하고 자동 종료는 없다(지금 동작 유지, Q9에서 확인).

## 3단계 — 갤러리 v2(D052·D053 (2))

규칙(D053 (2) 총괄 기본안): 최소 10장 첫 공개 = "첫 업로드", 촬영 종료 뒤 24시간 안. 공개 뒤 24시간 잠금 → 공개 7일째까지 추가·삭제·순서 변경. 구매 기한은 공개 뒤 7일 하나. 구매된 사진은 삭제 불가, 찜한 사진을 지우면 고객에게 알림. 추가 알림은 하루 1번으로 묶음. 서버 사진은 만든 뒤 30일 보관.

## 사용자·총괄이 정할 것

- **Q1 로그인 시점(고객)**: 지도 둘러보기는 로그인 없이(권장) / 앱을 열면 바로 로그인. 작가 앱은 처음부터 로그인(권장).
- **Q2 작가 등록**: 작가 앱 로그인만으로 작가가 되는지, 운영 승인(신원·계약)을 거치는지. 같은 계정으로 고객 앱도 쓸 수 있게 둘지.
- **Q3 시험 로그인**: sbsn-dev에서 자동 시험용 이메일·비밀번호 계정을 열어도 되는지(운영 프로젝트에서는 막음).
- **Q4 작가 기기**: 한 작가 계정이 폰 두 대에서 동시에 촬영 가능을 켤 수 있게 둘지.
- **Q5 동시 신청**: 고객이 여러 작가에게 동시에 신청할 수 있는지, 작가가 여러 신청을 받아 하나를 고르는지(나머지는 자동 거절).
- **Q6 휴게·제한·거절**: 휴게 중 신청 가능 여부, 제재 제한 중 지도 표시, 작가의 명시적 거절을 제재 집계에서 뺄지.
- **Q7 촬영 시간 상한**: 신청 단계에서 최대 몇 분까지(예: 60분), 연장 횟수 상한.
- **Q8 반경**: 촬영 가능 반경의 뜻(반경 밖 고객은 신청 불가 / 지도에만 표시)과 고를 값.
- **Q9 연장**: 작가 동의가 필요한지, 정한 시간이 지나면 지금처럼 진동만 하고 자동 종료하지 않을지.
- **Q10 사진 장수 상한**: 최소 10장의 위쪽 상한(고르기·업로드 시간과 연결).
- **Q11 미리보기 저장**: 워터마크 강도를 지금대로 둘지, 전체 저장을 갤러리 메뉴에 둘지.
- **Q12 전문보정**: 1인·2인 가격(D051 문구상 둘 다 5,000원), 보정본 자동 저장 여부, 보정본 메타데이터.

# 현장 실증 순서표

- 목적: 실제 카메라, 작가 폰 핫스팟, LTE, 밖에서 두 사람이 만나는 흐름으로 MVP 한 사이클을 끝까지 돌린다. 지금까지는 같은 와이파이에서 맥이 카메라 대신 사진을 보냈다(`docs/roadmap.md` "실증 결과").
- 서버 시각(확정, 작가 앱 받음, 시작, 미리보기, 찜, 구매, 고화질본, 고객 저장)은 자동으로 남는다. 사람은 결과(○ 됨, △ 늦거나 일부, × 안 됨)와 눈으로 본 것만 적는다.
- 끝나면 맥에서 `firebase/scripts/field_report_dev.py`로 시각표를 뽑아 맨 아래 "결과"에 붙인다.

## 준비물

- 카메라: a7C II(실증한 기종), a7 III(처음 붙여 봄). 배터리, 메모리 카드.
- 작가 폰(작가 앱, 핫스팟), 고객 폰(고객 앱, LTE). 두 사람. 작가 폰용 보조 배터리(선택).
- 두 앱 모두 c0565c3 이후 빌드.

## 출발 전(실내)

| # | 할 일 | 확인 |
|---|---|---|

## 실내 리허설(두 폰, 약 15분)

카메라마다 한 번씩 한다. a7 III는 여기서 처음 우리 FTP 서버에 붙는다.

| # | 할 일 | 기대 | 결과 | 메모 |
|---|---|---|---|---|
| R1 | 작가 "촬영 가능" 켬 → 고객 지도에서 작가 선택 → "이 작가와 촬영 확정" → 시작 전에 고객 "취소" | 작가 폰에 매칭 알림. 취소 뒤 작가 앱은 "촬영 가능"을 켠 채 대기로 돌아오고, 고객이 "지도로 돌아가기"를 누르면 작가가 다시 보인다 | | |
| R2 | 다시 확정 → 고객·작가 "촬영 시작" → 카메라를 핫스팟에 연결 → 2장 촬영 | 작가 촬영 화면에 2장, 고객 그리드에 미리보기 2장 | | |
| R3 | 작가 "촬영 종료" | 작가 앱이 전달을 마치고 대기로 돌아온다 | | |

## 끝난 뒤

1. 맥에서 시각표를 뽑는다(토큰은 출력하지 않는다).
   ```
   export SBSN_ADMIN_TOKEN="$(gcloud auth application-default print-access-token)"
   python3 -I firebase/scripts/field_report_dev.py latest <작가 uid>
   ```
   작가 uid는 작가 앱 홈 "개발"의 작가 ID다. 안드로이드 교차 시험도 sbsn-dev에 티켓을 만들기 때문에 uid 없이 `latest`만 쓰면 다른 티켓을 고를 수 있다.
2. 고객 폰 사진 앱에서 저장본 정보를 열어 JPEG인지 보고, 카카오톡으로 한 장 보내 열리는지 본다.
3. 문제가 있었던 단계는 작가 앱 티켓 폴더의 `session-log.txt`(FTP·업로드 기록)를 맥에 연결해 꺼내 본다.

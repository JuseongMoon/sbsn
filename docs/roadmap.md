# 십분스냅 MVP 로드맵

- 작성: 2026-10-27
- 방향(사용자 결정, 2026-10-26): 결제를 빼고 **한 사이클이 끝까지 도는지**를 먼저 실증한다. 깊은 기술 검증은 기록해 두고 V2로 미룬다.
- 설계 핵심(데이터 모델·보안 규칙·알림·iOS 전제)은 구현 전에 레드팀 세 축(규칙·데이터 모델 / 동시성·장애·운영 / iOS 플랫폼)으로 검증했다.

## 고객 최종본 형식: 원해상도 JPEG(2026-10-27 결정)

- 고객에게 넘기는 고화질본은 **JPEG**다. 메신저·윈도우·웹 어디서든 그대로 열린다. 작가 앱이 처음부터 JPEG로 만들어 올리고, 서버 사본과 고객 사진 앱 저장본이 같은 파일이다(앞으로 웹 다운로드 등 다른 경로를 붙여도 변환이 필요 없다).
- 크기(a7C II 원본 7008×4672·약 21MB 3장, ImageIO): HEIC q0.80 6.0MB / JPEG q0.80 7.1MB / **JPEG q0.85 8.7MB(채택)**. LTE 3~4Mbps에서 17~23초로, HEIC보다 장당 약 5~7초 늘었다.
- 카메라마다 들어오는 파일이 달라 작가 앱 한곳에서 맞춘다(`PhotoPreviewRenderer.renderFullResolutionJPEG`).
  - 회전 정보 없는 sRGB 8비트 JPEG(가로 사진 대부분): 그대로 다시 인코딩만 한다.
  - 세로 사진(EXIF 회전), Adobe RGB·Display P3, HEIF(10비트 포함), RAW: sRGB 8비트로 그려 회전을 픽셀에 반영한다. HDR(HLG·PQ) HEIF는 iOS 18 이상에서 SDR로 톤 매핑한다.
  - 메타데이터는 촬영 시각·노출·기종을 남기고 위치·일련번호·소유자·제조사 노트를 뺀다.
- 남은 판단: 4,500만~1억 화소 카메라는 원해상도 JPEG가 장당 13~25MB라 LTE에서 30~60초가 걸린다(추정). 긴 변 상한(예: 7008px, 3,300만 화소)을 둘지는 현장 실증과 작가 기종 조사 뒤 정한다. 렌더러에 `maxPixelSize`로 넣어 두었다.
- 카메라 설정 안내(작가용): FTP 전송은 JPEG(또는 HEIF), 색 공간 sRGB 권장, RAW+JPEG로 찍으면 JPEG만 전송, HDR 사진 모드는 끄기 권장(iOS 17 작가 폰에서는 톤 매핑이 없다).

## 데이터 모델(되돌리기 어려운 결정)

- `photographers/{uid}`: 작가 기기 FCM 토큰(비공개).
- `photographerPresence/{uid}`: 작가 공개 상태(이름, 촬영 가능, 100m 격자 위치, 갱신 시각, 매칭 잠금 `activeTicketId`, TTL `expiresAt`).
- `customers/{uid}`: 고객의 매칭 잠금 `activeTicketId`.
- `tickets/{autoId}`: 매칭 = 티켓. 고객이 확정 트랜잭션에서 만든다. 상태는 문자열 없이 시각 필드(`customerStartedAt`, `photographerStartedAt`, `photographerAckAt`, `endedAt`, `cancelledAt`)로만 바뀌고, 각 시각은 서버 시각으로 한 번만 쓴다.
  - 하위 `locations/{uid}`(서로의 위치), `messages/{autoId}`(채팅), `photos/{원본 파일명}`(미리보기·고화질본 경로, 찜·구매·전달 시각).
- 확정 트랜잭션 = 티켓 생성 + 작가 잠금 + 고객 잠금. 규칙이 `getAfter`로 세 쓰기를 묶어, 같은 작가를 두 고객이 동시에 확정하면 하나만 통과한다. 취소 트랜잭션은 잠금을 함께 푼다.
- Storage: 고화질본은 `fullres/<원본 파일명>.jpg`(image/jpeg). 참여자 확인은 작가 앱이 업로드 때 적는 객체 메타데이터(`customerUid`, `photographerUid`)로 한다. Storage 규칙은 한 번에 Firestore 문서를 2개까지만 읽을 수 있어, 고객의 고화질본 읽기에서만 사진 문서 하나(구매 여부)를 읽는다.
- 보존: `previews/`·`fullres/`는 30일 뒤 삭제, `photographerPresence`는 갱신이 24시간 없으면 삭제(`firebase/scripts/set_retention_dev.py`).

## 기대치와 한계(iOS·서비스 제약)

- 작가가 앱을 **쓸어 올려 종료하면** iOS가 알림으로 앱을 다시 실행하지 않는다. 위치 공유와 구매 업로드가 멈추고, 배너를 탭해 열어야 이어진다.
- 작가 앱은 "촬영 가능"인 동안 백그라운드 위치(When In Use + 백그라운드 모드 `location`)로 살아 있다. 상태 표시줄에 위치 표시가 뜨고 배터리를 쓴다.
- 백그라운드 구매 업로드는 알림 한 번에 한 장(깨어 있는 약 30초). 여러 장이나 느린 LTE는 앱이 앞으로 올 때 이어진다. 실패한 업로드는 앱이 앞으로 오거나 인터넷이 돌아오면 자동으로 다시 올린다.
- 촬영 종료 뒤에는 고화질본이 이미 올라간 사진만 살 수 있다. 작가 앱은 미리 올리기 시간(마지막 수신 뒤 30분) 안의 고화질본을 마저 올린 뒤 티켓을 놓는다.
- 고화질본(JPEG)은 30일 뒤 서버에서 지워진다. 고객 앱은 받자마자 사진 앱에 저장한다.
- 양쪽 모두 익명 로그인이다. 익명 계정은 키체인에 남아 앱을 지웠다 깔아도 같은 uid가 돌아올 수 있고, 반대로 기기를 바꾸면 이전 티켓에 접근할 수 없다. 시험할 때는 개발 메뉴의 "익명 계정 재발급"을 쓴다.
- 카메라가 재접속하면 못 보낸 사진을 다시 보내는지는 문서로 확인되지 않았다(실증 항목).

## 실증 결과

### 2026-10-27 실기기 한 사이클(sbsn-dev)

- 기기: 작가 iPhone 18 Pro Max(iP9), 고객 iPhone 12(iOS 18.7.2). 둘 다 같은 와이파이.
- 이 실증의 고화질본은 HEIC였다. 같은 날 최종본을 JPEG로 바꿨고, 실기기 JPEG 전달은 아래 "JPEG 최종본 확인"에 적었다.
- 조작: 맥에서 XCUITest 드라이버(`sbsnUITests/CycleDriverUITests.swift`)를 단계마다 실행했다. 카메라 대신 맥에서 작가 앱 FTP로 JPEG를 보냈다(4~12MB, 8장).
- 서버 시각은 관리자 권한으로 2초마다 읽어 기록했다(한국 시각).

| 단계 | 결과 |
|---|---|
| 촬영 가능 → 백그라운드 | 작가 앱을 홈으로 내린 뒤 40분 동안 3분마다 공개 상태를 갱신했다(백그라운드 위치로 앱이 살아 있음). 폰이 잠긴 동안에도 같았다. |
| 고객 확정 → 작가 앱 받음 | 티켓 생성 09:56:16.352 → `photographerAckAt` 09:56:16.672(0.3초). 작가 앱은 백그라운드·잠금 상태였다. 매칭 알림도 FCM으로 발송됐다. |
| 위치·채팅 | 고객 위치 0.4초, 작가 위치 3초 뒤 티켓에 올라옴. 고객 채팅 → 작가 화면에 표시, 채팅 알림 발송. |
| 양측 시작 | 작가 시작 → 고객 시작 → 양쪽 촬영 화면. |
| 미리보기 | 수신 뒤 약 2초에 서버 저장, 고객 그리드에 6장 표시. 워터마크 확인. |
| 구매(고화질본 미리 올라감, 작가 앱 앞) | 구매 10:23:03.859 → 고객 사진 앱 저장 10:23:04.952(1.1초). |
| 구매(고화질본 없음, 작가 앱 백그라운드) | 구매 10:25:30.513 → 작가 앱 고화질본 업로드 10:25:32.793 → 고객 저장 10:25:34.009(3.5초). |
| 작가 앱 재시작 | 다시 실행하자 촬영 화면과 사진 6장·업로드 상태가 복원되고 FTP가 다시 열렸다. 고객 앱을 다시 설치해도 진행 중인 티켓으로 돌아왔다. |
| 촬영 종료 | 작가 잠금 해제·촬영 가능 꺼짐, 고객 잠금 해제. 종료 뒤 고화질본 없는 사진은 구매 버튼 없음, 있는 사진은 구매 가능. 작가 앱은 전달을 마치고 홈으로 돌아옴. |

실기기에서 찾아 고친 것
- 고객 지도가 기본 위치(서울 시청)에 머물러 멀리 있는 작가 마커가 화면 밖에 있었다 → 작가가 처음 보일 때 작가들이 모두 보이게 맞춘다.
- 구매 버튼이 사진 앱 권한 창에 답할 때까지 구매 기록을 미뤘다(3분 지연) → 구매를 먼저 기록하고 권한은 그다음에 묻는다.
- 사진 목록 리스너가 그리드 화면 task에 있어 상세 화면에 들어가면 취소됐다(상세에서 산 사진이 내려받아지지 않고 화면도 갱신되지 않음) → 티켓 단위 전달 관리자가 듣는다.

이번에 확인하지 않은 것
- 실제 카메라·핫스팟·셀룰러(LTE) 회선. 이전 실증(2026-10-22, 10-25)의 LTE 수치가 기준이다.
- 작가가 앱을 쓸어 올려 종료한 뒤 배너 탭으로 이어 가기, 시스템 종료 뒤 알림으로 깨어난 복원.
- 취소 흐름(규칙은 129개 시나리오로 확인), 10분 넘게 조용한 작가 숨김, 알림 배너 표시 모양(발송은 함수 로그로 확인).

### 2026-10-27 JPEG 최종본 확인(같은 기기, 같은 와이파이)

- Storage 규칙(`.jpg` 기준)을 sbsn-dev에 배포한 뒤 규칙 시나리오 129/129 통과.
- 맥에서 작가 앱 FTP로 4장을 보냈다. 고화질본을 관리자 권한으로 내려받아 검사했다. 모두 `image/jpeg`이고 회전 1·8비트·sRGB였다.

| 입력 | 고화질본 |
|---|---|
| a7C II 원본 가로(7008×4672, 20.9MB, sRGB) | 7008×4672, 8.7MB. 촬영 시각·기종 유지 |
| a7C II 원본에 세로 회전(EXIF 6)·GPS·렌즈 일련번호를 넣은 것 | 4672×7008(회전이 픽셀에 반영됨), 9.4MB. GPS·일련번호 없음 |
| Display P3 JPEG(6016×6016) | sRGB로 바뀜, 3.9MB |

- 고객 구매 → 사진 앱 저장(`deliveredAt`)은 4장 모두 서버 시각 0.8~1.4초 안에 끝났다(고화질본이 미리 올라간 경우).
- 작가 앱을 다시 설치하자 촬영 중 티켓·사진 3장·업로드 상태가 복원되고 FTP가 다시 열렸다.
- 찾아 고친 것: 가장 흔한 입력(가로 sRGB JPEG)이 타는 빠른 경로(`CGImageDestinationAddImageFromSource`)는 넘긴 메타데이터를 원본 위에 덮어쓰기만 해서 **카메라 본체 일련번호와 GPS가 고화질본에 남았다.** 이미지만 꺼내 `CGImageDestinationAddImage`로 쓰도록 바꿨다(시간 0.30초·크기 같음). 단위 테스트에 이 경로의 개인정보 제거를 추가했다.
- 확인하지 못한 것: 고객 폰 사진 앱 안에서 본 형식. 사진 앱이 Face ID로 잠겨 있었다. 앱은 `.jpg` 파일을 그대로 사진 앱에 넘긴다.

## V2로 미룬 것

- 결제·정산·App Store 3.1.1 검토(사용자가 다시 꺼낼 때). 고객의 `purchasedAt` 쓰기를 서버 전용으로 바꾸고 결제 대기 상태·주문 원장·가격 스냅샷을 더한다. 구매 취소·환불 정책. 화면 문구는 "촬영 서비스"로 일관.
- 원본 JPEG 나중 전달과 고객 푸시 알림, 티켓 "닫기"
- Always 위치 권한·지오펜스, 작가 수락·거절, 지오해시 셀 쿼리(작가가 많아지면 지도 리스너 비용), App Check, 작가 프로필·포트폴리오·평점, 정식 로그인(익명 계정 연결)
- 채팅 신고·차단(App Store 1.2), 개인정보 처리방침, 외부 테스트 심사
- 위치정보법: 위치기반서비스사업 신고는 **완료**(신고번호 1628, 2026-09-22). 남은 것은 다음과 같다.
  - 변경신고 필요 여부 확인: 신고 때 낸 위치정보시스템(서버 등 주요설비)에 이 서비스의 Firebase(서울)가 없으면 변경신고 대상이다(법 제9조제3항, 시행령 제9조제2항).
  - 이용약관 명시·동의 화면(제15조, 제19조제1·2항): 작가는 위치를 고객 지도와 매칭 고객에게 제공하는 데, 고객은 위치를 매칭 작가에게 제공하는 데 동의한다.
  - 제3자 제공 통보(제19조제3·4항): 매회 즉시 통보, 또는 동의를 받아 최대 30일 단위로 모아 통보한다. 공개 지도의 위치 제공을 어떻게 볼지 확인한다.
  - 수집·이용·제공 사실 확인자료 자동 기록·보존과 보호조치(제16조), 정보주체 권리(제24조: 동의 철회·일시 중지·열람, 철회 시 파기).

# 십분스냅 MVP 로드맵

- 작성: 2026-10-27
- 방향(사용자 결정, 2026-10-26): 결제를 빼고 **한 사이클이 끝까지 도는지**를 먼저 실증한다. 깊은 기술 검증은 기록해 두고 V2로 미룬다.
- 설계 핵심(데이터 모델·보안 규칙·알림·iOS 전제)은 구현 전에 레드팀 세 축(규칙·데이터 모델 / 동시성·장애·운영 / iOS 플랫폼)으로 검증했다.
- **2026-11-21 전환(D036~D043)**: 촬영 중 실시간 FTP 전달 대신 **작가 선별 업로드**가 기본 흐름이 됐다.
  - 촬영이 끝나면 작가가 사진을 폰으로 옮겨 5~8장을 고르고 한 번 공개한다.
  - 실시간 FTP는 두 앱에서 걷어냈다(보관 태그 `archive/live-ftp-v1`, `docs/archive/live-ftp.md`).
  - 동작 정본은 `docs/design/curated-upload.md`, 공통 명세는 총괄 `Docs/PRODUCT_SPEC.md` "선별 전달 공통 명세"다.
  - 아래 "실증 결과"의 10월 기록은 실시간 FTP 시기의 것이다.

## 고객 최종본 형식: 원해상도 JPEG(2026-10-27 결정)

- 고객에게 넘기는 고화질본은 **JPEG**다. 메신저·윈도우·웹 어디서든 그대로 열린다. 작가 앱이 처음부터 JPEG로 만들어 올리고, 서버 사본과 고객 사진 앱 저장본이 같은 파일이다(앞으로 웹 다운로드 등 다른 경로를 붙여도 변환이 필요 없다).
- 크기(a7C II 원본 7008×4672·약 21MB 3장, ImageIO): HEIC q0.80 6.0MB / JPEG q0.80 7.1MB / **JPEG q0.85 8.7MB(채택)**. LTE 3~4Mbps에서 17~23초로, HEIC보다 장당 약 5~7초 늘었다.
- 카메라마다 들어오는 파일이 달라 작가 앱 한곳에서 맞춘다(`PhotoPreviewRenderer.renderFullResolutionJPEG`).
  - 회전 정보 없는 sRGB 8비트 JPEG(가로 사진 대부분): 그대로 다시 인코딩만 한다.
  - 세로 사진(EXIF 회전), Adobe RGB·Display P3, HEIF(10비트 포함): sRGB 8비트로 그려 회전을 픽셀에 반영한다. HDR(HLG·PQ) HEIF는 iOS 18 이상에서 SDR로 톤 매핑한다.
  - 메타데이터는 **작가가 올린 파일 것을 전부 유지**한다(D037, 2026-11-21). 위치·일련번호·소유자·MakerNote·IPTC·XMP를 모두 남긴다.
    - JPEG는 원본 세그먼트를 바이트로 옮기고 회전·크기·색 공간만 고친다(`JPEGMetadataTransplant`). HEIF는 메타데이터 트리로 옮긴다(MakerNote는 빠질 수 있다).
    - 이전의 허용 목록(30개)은 없앴다. 작가 화면에 "메타데이터는 구매한 고객에게 그대로 전달됩니다" 고지를 둔다.
  - 6,000만 화소를 넘는 원본은 긴 변 8192로 줄인다(D013). 고화질본이 50MiB 이상이면 품질 0.80·0.75로 다시 만들고, 그래도 넘으면 받지 않는다.
- 남은 판단: 4,500만~1억 화소 카메라는 원해상도 JPEG가 장당 13~25MB라 LTE에서 30~60초가 걸린다(추정). 긴 변 상한(예: 7008px, 3,300만 화소)을 둘지는 현장 실증과 작가 기종 조사 뒤 정한다. 렌더러에 `maxPixelSize`로 넣어 두었다.
- 카메라 설정 안내(작가용): 파일 형식은 JPEG, 색 공간 sRGB 권장, RAW+JPEG로 찍으면 JPEG만 전송, HDR 사진 모드는 끈다.

### 작가 입력 형식: JPEG·HEIC/HEIF만(D040 ③, 2026-11-21)

- 선별 업로드는 사진 선택기(`.current`, 권한 창 없음)나 파일 앱으로 고른다.
  - 시뮬레이터에서 선택기 세 경로 모두 원본과 바이트까지 같았다. 다만 `.compatible`은 HEIC를 JPEG로 바꾸며 XMP를 버려 쓰지 않는다.
- 받는 것: JPEG·HEIC/HEIF, 긴 변 4,000px 이상(PROV-04).
- 막는 것: RAW("JPEG로 내보내 주세요"), 열 수 없는 형식. 촬영 시각이 촬영 시간대 밖이면 경고만 한다.
- 2026-10-27의 "카메라 입력은 JPEG만"(FTP로 받던 카메라 HEIF 10비트 문제)은 이 결정으로 바뀌었다. 카메라 설정 안내와 실기기 기록은 `docs/archive/live-ftp.md`가 가리키는 보관 태그에 있다.

## 데이터 모델(되돌리기 어려운 결정)

- `photographers/{uid}`: 작가 기기 FCM 토큰(비공개).
- `photographerPresence/{uid}`: 작가 공개 상태(이름, 촬영 가능, 100m 격자 위치, 갱신 시각, 매칭 잠금 `activeTicketId`, TTL `expiresAt`).
- `customers/{uid}`: 고객의 매칭 잠금 `activeTicketId`.
- `tickets/{autoId}`: 매칭 = 티켓. 고객이 확정 트랜잭션에서 만든다. 상태는 문자열 없이 시각 필드(`customerStartedAt`, `photographerStartedAt`, `photographerAckAt`, `endedAt`, `cancelledAt`)로만 바뀌고, 각 시각은 서버 시각으로 한 번만 쓴다.
  - 하위 `locations/{uid}`(서로의 위치), `messages/{autoId}`(채팅), `photos/{사진 ID}`(작가 초안: 표시용 `fileName`·`capturedAt`·미리보기·고화질본 경로와 바이트 수, 고객: 찜·구매·전달 시각).
  - 선별 티켓(D038): `deliveryMode: "curatedV1"`(확정 때 한 번), `galleryPublishedAt`·`galleryPhotoIds`(5~8개, 공개 순서). 서버 함수 `publishGallery`만 쓴다.
  - 사진 ID는 `^p[a-z0-9]{12}$`다. 파일 내용마다 새로 발급하고, 재시도는 같은 ID를 쓴다.
  - 고객은 공개 전에 아무것도 못 보고, 공개 뒤 공개 목록 문서를 하나씩 읽는다(목록 조회 불가).
- 확정 트랜잭션 = 티켓 생성 + 작가 잠금 + 고객 잠금. 규칙이 `getAfter`로 세 쓰기를 묶어, 같은 작가를 두 고객이 동시에 확정하면 하나만 통과한다. 취소 트랜잭션은 잠금을 함께 푼다.
- Storage: 미리보기 `previews/<사진 ID>.jpg`(1MB 미만), 고화질본 `fullres/<사진 ID>.jpg`(image/jpeg, 50MiB 미만). 만들기만 되고 덮어쓰기·삭제는 안 된다. 객체 메타데이터는 `customerUid`·`photographerUid` 두 키만 둔다. 참여자 확인은 작가 앱이 업로드 때 적는 객체 메타데이터(`customerUid`, `photographerUid`)로 한다. Storage 규칙은 한 번에 Firestore 문서를 2개까지만 읽을 수 있어, 고객의 고화질본 읽기에서만 사진 문서 하나(구매 여부)를 읽는다.
- 보존: `previews/`·`fullres/`는 30일 뒤 삭제, `photographerPresence`는 갱신이 24시간 없으면 삭제(백엔드 저장소(웹 프로젝트)의 `firebase/scripts/set_retention_dev.py`).

## 기대치와 한계(iOS·서비스 제약)

- 작가 앱은 "촬영 가능"과 만나기 동안 백그라운드 위치(When In Use + 백그라운드 모드 `location`)로 살아 있다. 촬영이 시작되면 위치 추적을 끈다.
- 고른 사진의 렌더는 앱이 앞에 있을 때 한다. 고화질본은 앞에서 시작하면 iOS 백그라운드 전송(`putFile`)으로 보내, 작가가 다른 앱을 써도 이어진다.
  - 앱을 쓸어 올려 끄면 렌더와 공개 예약은 다음에 앱을 열 때 이어진다(`selection.json`과 서버 기록으로 복원).
- 공개는 티켓당 한 번이다. 공개한 뒤에는 사진을 더하거나 빼거나 순서를 바꿀 수 없다.
- 작가는 공개 전에도 다음 매칭을 받는다(D040). 종료 30분 뒤에도 공개하지 않았으면 작가 앱이 다시 알리고, 고객 화면에 지연 안내가 뜬다.
- 구매는 공개 뒤 168시간 안에만 된다(서버 강제). 고화질본은 공개 전에 이미 올라가 있어 구매 즉시 내려받는다.
  - 서버 파일은 만든 뒤 30일에 지워지므로, 고객 앱은 받자마자 사진 앱에 저장한다.
- 고객이 시작 전에 취소하면 작가 앱은 티켓을 놓고 대기로 돌아간다. 앱이 화면에 없으면 로컬 알림을 띄우고, 홈에 안내를 남긴다.
- 양쪽 모두 익명 로그인이다. 기기를 바꾸면 이전 티켓에 접근할 수 없다. 시험할 때는 개발 메뉴의 "익명 계정 재발급"을 쓴다.
- 전환(sbsn-dev 배포) 뒤에는 옛 빌드와 안드로이드 앱으로 새 촬영을 할 수 없다(D043, iOS만 먼저 D041).

## 실증 결과

아래 10월 기록은 실시간 FTP 시기(보관 태그 `archive/live-ftp-v1`)의 것이다. 선별 흐름의 실기기 결과는 sbsn-dev 전환 뒤 이어서 적는다.

### 2026-10-27 실기기 한 사이클(sbsn-dev)

- 기기: 작가 iPhone 18 Pro Max(iP9), 고객 iPhone 12(iOS 18.7.2). 둘 다 같은 와이파이.
- 이 실증의 고화질본은 HEIC였다. 같은 날 최종본을 JPEG로 바꿨고, 실기기 JPEG 전달은 아래 "JPEG 최종본 확인"에 적었다.
- 조작: 맥에서 XCUITest 드라이버(`sbsnUITests/CycleDriverUITests.swift`)를 단계마다 실행했다. 카메라 대신 맥에서 작가 앱 FTP로 JPEG를 보냈다(4~12MB, 8장).
- 서버 시각은 관리자 권한으로 2초마다 읽어 기록했다(한국 시각).

| 단계 | 결과 |
|---|---|
| 촬영 가능 → 백그라운드 | 작가 앱을 홈으로 내린 뒤 40분 동안 3분마다 공개 상태를 갱신했다(백그라운드 위치로 앱이 살아 있음). 폰이 잠긴 동안에도 같았다. |

| 위치·채팅 | 고객 위치 0.4초, 작가 위치 3초 뒤 티켓에 올라옴. 고객 채팅 → 작가 화면에 표시, 채팅 알림 발송. |

실기기에서 찾아 고친 것
- 고객 지도가 기본 위치(서울 시청)에 머물러 멀리 있는 작가 마커가 화면 밖에 있었다 → 작가가 처음 보일 때 작가들이 모두 보이게 맞춘다.
- 구매 버튼이 사진 앱 권한 창에 답할 때까지 구매 기록을 미뤘다(3분 지연) → 구매를 먼저 기록하고 권한은 그다음에 묻는다.
- 사진 목록 리스너가 그리드 화면 task에 있어 상세 화면에 들어가면 취소됐다(상세에서 산 사진이 내려받아지지 않고 화면도 갱신되지 않음) → 티켓 단위 전달 관리자가 듣는다.

이번에 확인하지 않은 것
- 실제 카메라·핫스팟·셀룰러(LTE) 회선. 이전 실증(2026-10-22, 10-25)의 LTE 수치가 기준이다.
- 작가가 앱을 쓸어 올려 종료한 뒤 배너 탭으로 이어 가기, 시스템 종료 뒤 알림으로 깨어난 복원.
  - 시스템 종료 뒤 복원은 2026-10-28에 확인했다(아래).
- 현장 실증 순서표와 실증 뒤 시각표 도구: `docs/field-test.md`, 백엔드 저장소(웹 프로젝트)의 `firebase/scripts/field_report_dev.py`.
- 취소 흐름(규칙은 129개 시나리오로 확인), 10분 넘게 조용한 작가 숨김, 알림 배너 표시 모양(발송은 함수 로그로 확인).
